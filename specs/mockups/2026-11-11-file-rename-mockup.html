Delete the trashed item and rename?

A trashed item already uses the name Beach 2006-08.jpg. It is not on disk. Renaming deletes it permanently, with its albums, faces and edits.

Beach 2006-08.jpg Trashed 3 Nov 2026
Placement. The pencil sits on the filename row, next to the existing location button. The date row already has an owner-only pencil for the same kind of edit.
Why not the overflow menu. The filename is already in the info panel, and the viewer's overflow menu already holds many actions. Two entry points for one value would drift apart, so the mockup uses one.
Who can rename. Owners only, gated like the date pencil. A space viewer sees the filename and location button with no pencil (stage 5).
Dialog. The name field is the filename without its extension. The extension is shown after the field and cannot be changed here. On save, the extension is normalized as a templated rename does (for example .JPEG becomes .jpg).
Also rename on disk (stage 3). The external library dialog adds one checkbox, unchecked by default. Unchecked changes only the name Gallery shows. Checked also renames the file on disk, with its sidecar.
Which dialog. Stage 2 is for user-library assets. Their display name changes and the file never does, so it has no checkbox. Stage 3 is for external-library assets and adds the checkbox.
Extension. Every rename writes the normalized extension to the name Gallery shows, checked or not. Only a checked external rename also changes the file on disk, so the disk may keep its own extension (spec open question 16, decided).
Name checks (stages 6 and 7). They apply only when "Also rename on disk" is checked. Unchecked, the path does not change, so nothing can clash.
Live check (stage 6). While the user types, and when the box is ticked, the dialog asks the server whether the new file name is free. A file already at that path shows the red message and greys out Rename. The server checks again when Rename is pressed, so a name taken in the meantime is refused.
Trashed item (stage 7). If the name is held by an item the user trashed (its file is not on disk), pressing Rename opens this confirmation. Cancel goes back to the rename dialog.
Offline item (no dialog). If the name is held by an item that went offline because its file disappeared, the row is deleted and the rename goes ahead, with no extra step.
Live photos. The name is checked for both files of the pair. Either one clashing blocks the rename.
