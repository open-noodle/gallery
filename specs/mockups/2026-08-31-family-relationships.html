Family relationships — UI

Drawn against the real components, not just the colour tokens: the detail panel is grid-cols-3 with ImageThumbnail curve shadow exactly as DetailPanelPeople.svelte renders it; the person header is the 3.375rem circle from the person page; the sidebar is the real nav list from UserSidebar.svelte with one item added.

Layout and density were validated against a real library — the thumbnails below are those real photographs reduced to 4×4 pixels and blurred, so tile sizing, tonal weight and how a grid of faces actually reads are all true to life, while no individual is identifiable.

Nothing here is real personal data. open-noodle/gallery is public, so the committed mockup carries no identifiable faces and no real names — the images in family-placeholder/ are unidentifiable colour fields, and every name is invented, as are all the relationships between them. Regenerate against live data locally if you need to re-check fidelity; keep it out of the commit.

This is the surface that does the actual orientation job. Open a photo of half-familiar faces and read how each one relates to you, without navigating anywhere.

Casper is a known person with no recorded relationship, so the line is a neutral dash rather than blank — a blank makes the grid ragged and reads as a loading state.

Relation is an added line, not a replacement — the existing age line stays. Lena, Nico and Juno show both; Oskar has no birthdate; Casper has a birthdate but no recorded relationship. That mix is the normal case, and it means rows will differ in height. CSS grid equalises tiles within a row so it reads as variation rather than breakage — and reserving an empty line to force uniformity would cost every tile the height whether it uses it or not.

At more than six people the real component switches to grid-cols-4 gap-2 and drops the sub-lines to text-xs. Four lines at four columns in a ~360px panel is tight, so the relation truncates with an ellipsis there — that crowded case is the one worth testing, not the roomy one shown here.

The third is what stops the feature feeling broken. With no path from your root to someone, describe them relative to the nearest person you do reach — "Mia's parent" — rather than showing a blank.

One state deliberately has no design: a user whose effective access is none sees no relations section, no detail-panel lines, and no Family item in the sidebar at all — not a locked or empty version. An empty state would advertise a feature they cannot use and imply relationships exist.
