(`tools/upstream-preflight/src/rolling.ts:387-403`) rather than rebuilding rolling from `main`'s
commit set, so rolling-only commits survive every batch.

onto an upstream that had already made the change. The 614 pure deletions co-resolved silently
(both sides delete). What conflicted was the **additive** surface and, more numerously, historical
fork commits that had edited the now-deleted generated files.

**Verified before accepting any deletion:** batch 12's deletion set is 59 paths, entirely
`mobile/test/drift/main/generated/` (32), `mobile/lib/infrastructure/entities/` (25) and

v32–v36) are the source of truth and were untouched, accepting the deletions is lossless: the
artifacts are regenerated by `mise //mobile:codegen`.

### Conflict: `mobile/pubspec.yaml` (batch 13, three separate commits)

- **At the squashed fork base**: upstream renamed the analyzer exclude `openapi/**` → `generated/**`
  while the fork added a `patrol:` block. **Resolution**: took upstream's rename and preserved the

- **At fork commit `43006583a98` (#114, "remove patrol dependency")**: the fork's own later commit
  removes that block. **Resolution**: accepted the removal — final state has no `patrol:` block,
  which is the fork's intent. (Preserving it at the base was still correct; dropping it there would
  have made #114 a no-op and hidden the fork's history.)
- **At the fork's adoption commit**: fork had `- generated/openapi/**`, upstream has
  `- generated/**`. **Resolution**: took upstream's — it is the broader superset and upstream now
  owns this line. No fork-only content lost.
- **Risk**: LOW. **Verification**: fork's `version: 1.0.0+1` (stamped at build time by
  `apply-branding`) confirmed preserved against the pre-rebase tree, not overwritten by upstream's
  `3.1.0+3057`.
