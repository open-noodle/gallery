Design proposal · issue #473

Mobile filters, at the scale of thousands.

The iOS/Android filter sheet renders every person, place and tag in one flat, unbounded list — no collapse, no search. With hundreds of people and thousands of locations it becomes unusable. This proposal brings the sheet to parity with the web filter panel: collapsible & hideable sections, capped previews, and a dedicated full-screen search picker for every large dimension.

Parity target · web filter‑panel Platform · Flutter (iOS + Android) Reporter · “hundreds of people, thousands of locations, 10k+ tags”
Where it breaks today

Three failures, one flat list.

Every filter surface in the live sheet — both the browse strips and the deep sections — builds the full server list eagerly. The server applies no LIMIT; the client applies no cap and no windowing.

01 · UNBOUNDED

Renders everything

People are a Wrap over the whole list; Places builds a chip per country and per city; Tags the same. Thousands of widgets, built at once.

02 · NO COLLAPSE

Can't be tidied

Sections can't be collapsed or hidden. To reach “Media type” you scroll past every person and place. The exact ask in the issue title.

03 · NO SEARCH

Can't be found

No “Search people / locations”. People has a decent full-screen picker — but it reads local Drift (misses shared-space people) and Places / Tags / Camera have no picker at all.

Live code: people_section.widget.dart:47 · places_cascade_section.widget.dart:50 & :98 · tags_section.widget.dart:29 · buildFilteredGlobalPeopleQuery has no LIMIT

The proposal in three moves

Collapse it. Cap it. Search it.

1

Collapsible & hideable sections

Every section becomes an accordion with a remembered open/closed state (empty ones auto-collapse & disable). A “Manage sections” sheet lets users remove whole categories — web's two-axis model, ported.

2

Capped previews + “Show more”

Each section shows only the first N (People 6, Places/Tags/Camera 10), matching the web counts. No more eager thousand-widget builds; the rest lives one tap away.

3

Full-screen search pickers

A “Search N →” row opens a dedicated screen with a search field, A–Z scrubber and recent/selected strips — for People (reconciled to server + shared spaces), Places, Tags and the new Camera dimension.

The redesigned sheet

Two snaps, both bounded.

The draggable sheet keeps its two snap points — Browse (quick, horizontal strips) and Deep (full accordion). Both now cap what they render and route to pickers. Tap a section header to collapse it.

What changed
1

Capped preview

People shows the first 6; Places / Tags / Camera the first 10. Selected-but-hidden items stay pinned & checked (web's “orphan” handling).

2

Browse strips cap too

Horizontal strips end in a +N tile that opens the same picker — no more thousand-avatar ListView.

3

“Search N →” row

Opens the full-screen picker for that dimension. The one escalation path for scale, consistent across People, Places, Tags, Camera.

4

Collapsible accordions

Tap any header to collapse. State is remembered per session; empty sections auto-collapse & disable. (Try tapping the headers in this mockup.)

5

Active-filter chips — unchanged

Kept exactly as today: the existing timeline subheader (PhotosFilterSubheader), shown above the sheet — not moved into the sheet. Staying with the current codebase until the core lands; occluded while the sheet is deep, as today.

6

Manage sections

The ⚙︎ in the deep-sheet header (next to Reset) opens the hide/show sheet (below). Lets users strip the sheet down to only the filters they use.

The escalation path

One picker pattern, four dimensions.

Every “Search N →” lands on the same anatomy: a search field, contextual strips, and a windowed list that scales to any size. People already has this — we reconcile its data source and clone it for Places, Tags and Camera.

Entry point & behavior
⚙

Reached from the deep-sheet header

A ⚙︎ “manage” icon sits next to Reset in the deep sheet header. Tapping it opens this sheet. It appears only at the deep snap — the browse snap stays minimal.

✓

Collapse ≠ hide

Collapse tidies temporarily; hide removes a category you never use (e.g. Camera) from the sheet entirely. Web ships both — expanded-sections and visible-sections, each persisted.

✓

Hidden ≠ inactive

A hidden section's active filters keep applying and stay removable via the existing timeline chip bar (visible when the sheet is closed) — you can never “lose” a filter behind a hidden section.

✓

Sensible defaults

All sections visible out of the box; only power users need to touch this. Empty sections already auto-collapse, so most people never open it.

Decisions & open questions

Settled, and still open.

Full-screen pickers Camera included Accordion + hide sections People → server + shared spaces
Tags data source at scale

With 10k+ tags, does the picker load the full tag list client-side (fast search, big payload) or query the server per keystroke? Web uses the context-narrowed suggestion set only.

Lean: reuse existing getAllTags (flat, value = full path) — already cached in tagProvider; client-side search.
Context-narrowing in pickers

Web's inline search filters the context-narrowed suggestion set (people who appear under current filters). A full-screen picker browsing all people is friendlier, but can select a person with 0 results under the active filter.

Lean: browse the full set — show live match count, like web's orphan handling.
Places multi-select?

The model holds a single location and web is single-select too. Keeping single-select is parity & low-risk; multi-select would need a model + server change.

Lean: keep single-select — out of scope for this pass.
Retire the dead upstream UI?

An orphaned upstream filter UI (widgets/search/search_filter/ + its providers) is unreferenced. Delete as part of this, or leave it?

Lean: delete — reduces confusion while we're in the area.
